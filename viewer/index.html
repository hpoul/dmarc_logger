Reading the status

  • Aligned DKIM and SPF both pass for the From domain. Nothing to do.
  • SPF only Passes because of the sending IP alone, with no aligned DKIM signature. Breaks when the mail is forwarded, and it is what unsigned mail from a trusted server looks like.
  • DKIM only Signed, but sent from an IP your SPF record does not list. Usually a forwarder or mailing list; fine as long as the signature holds.
  • Failing Most messages fail DMARC. Either somebody else is sending as the domain, or a server of yours is neither listed in SPF nor signing. With p=quarantine these land in spam.

Failure causes, one label per row as written by dmarc_logger:

  • ok DMARC passed.
  • forwarded The receiver overrode the policy for a forwarding reason.
  • verdict-differs This tool computed an aligned pass but the receiver reported fail on both mechanisms.
  • temperror A transient DNS error left the verdict provisional.
  • dkim-unaligned A signature passed, but for a third-party domain.
  • spf-unaligned SPF passed, but for a third-party domain.
  • dkim-broken DKIM failed definitively (fail, policy, permerror).
  • spf-not-listed SPF failed (fail, softfail, permerror).
  • unsigned Neither mechanism produced a signal.
  • unrecognized A result value outside the RFC set.
